# 阶段 32：可视化推理性能测试与 AI 分析

自动测试：

```bash
./scripts/accept-stage-32.sh
```

自动测试使用本机临时 OpenAI-compatible 服务，不会向真实模型施加负载。它验证模型自动发现、
并发请求、预热排除、实际 Token 统计、延迟分位数、结果持久化、取消以及只访问本机已登记端口。

真实服务人工测试：

1. 保持一个平台部署或 AI 部署结果对应的推理服务运行。
2. 平台托管服务：打开“部署中心”的运行中任务详情，点击“性能测试”。AI 部署：打开 AI 会话的已验证部署结果，点击“性能测试”。
3. 首次建议使用低负载参数：近似输入 `128`、最大输出 `16`、并发 `1`、正式请求 `3`、预热 `1`、超时 `120` 秒。
4. 点击“开始测试”后应立即跳到“性能测试”页面，实时显示完成请求数和百分比；浏览器关闭不会终止后台测试。
5. 完成后确认显示成功率、请求吞吐（req/s）、输出/总 Token 吞吐、平均延迟、P50/P95/P99、实际平均输入/输出 Token 和耗时。
6. 逐步把并发改为 `2`、`4`、`8`，使用“再次测试”保持其他参数不变，观察吞吐、延迟与系统监控中的双机 GPU/CPU/统一内存变化。不要一开始使用最大并发。
7. 启动一个较长测试并点击“取消测试”，状态应变为“已取消”；已经发出的 HTTP 请求可能在服务端完成，但平台不会再发新请求。
8. 在完成结果上点击“交给 AI 分析”，确认 AI 配置窗口包含参数和汇总指标，不包含测试 Prompt 或模型响应正文。启动后让 AI 给出瓶颈判断和下一组测试矩阵。

说明：配置的输入 Token 是中性文本构造目标，最终报告以推理服务 `usage` 返回的实际 Token 数为准；模型可能因 EOS 提前结束，所以实际输出可能小于最大输出。平台执行可复现负载，AI 负责分析，不让 AI 临时编写不同口径的压测脚本。

通过标准：测试过程可视化、可以取消和复跑，结果可持久化比较，并能安全交给 AI 分析；服务请求内容和响应正文不写入数据库。
