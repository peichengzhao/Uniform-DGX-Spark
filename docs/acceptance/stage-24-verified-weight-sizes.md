# 阶段 24：真实权重大小与量化修正

本阶段修复以逻辑参数统计推算物理文件大小造成的偏差。模型卡片进入可视区域时，后端按需读取
Hugging Face 或 ModelScope 的文件清单，汇总实际权重分片并缓存结果。搜索本身不等待几十个
详情请求，文件元数据最多三个并发。

普通 safetensors/bin 权重显示分片总和；GGUF 仓库含多个量化文件时显示单文件最小到最大范围，
不把全部可选量化版本相加。卡片将“权重下载”和“仓库总量”分开。NVFP4、AWQ、GPTQ、GGUF
等模型名称中的明确量化格式优先于过于笼统的 `quant_method`。

NVFP4 优先级和详情 API。

## 浏览器人工测试

1. `Ctrl+Shift+R` 刷新 `http://127.0.0.1:18180`，搜索
   `deepseek-ai/DeepSeek-V4-Flash-Vision-Exp`。
2. 卡片刚出现时可能短暂显示“读取中…”，随后“权重下载”应约为 `156.3 GiB`，“仓库总量”
   也约为 `156.3 GiB`，不能再显示约 `291.5 GiB`。
3. 搜索 `webbrain-one/DeepSeek-V4-Flash-Vision-NVFP4`，量化/精度应显示 `NVFP4`，而不是 FP8。
4. 搜索包含多个 GGUF 量化文件的仓库。权重下载应显示“最小–最大/文件”，仓库总量可显示所有
   文件之和；两者不能混为一个数字。
5. 返回同一模型或刷新页面，验证过的大小应从本地缓存快速返回，不再重复读取远端文件清单。

通过标准：DeepSeek 官方模型显示实际 48 个权重分片总和；NVFP4 标签正确；GGUF 不合计多个
可选版本；搜索切换不因文件详情加载而阻塞。

本阶段只读取远端文件元数据，不下载权重内容、不启动或停止容器，无需清理资源。
