# AI 一键模型精度评测：开发与验收

日期：2026-10-23。用户明确授权在阶段 41 的现有评测后台上增加 AI 编排；不扩展数据集、Judge、
代码执行或多模态评测，不重写 EvalScope 的评分逻辑。

## 使用方式

1. 打开“精度评测”，选择已运行的模型，点击“AI 一键评测”。原来的“手动配置”仍保留。
2. 输入需求，例如“评测数学和中文能力，先做小规模测试”，设置最大样本预算（默认 100，包含试跑）。
   Codex 模型和思考强度可以沿用平台当前设置，也可以显式填写。
3. Codex 通过专用工具检查环境、选择已有的 GSM8K/ARC/C-Eval 子集并提交方案。
4. 阅读方案的数据集、每子集样本数、few-shot、生成参数以及“试跑＋正式”的最大样本数。
   在页面点“确认方案并开始评测”之前，平台不会发起模型评测。
5. 平台先按相同参数对每个子集最多试跑 2 条；试跑完整成功后，才执行确认的正式样本上限。
   正式规模不大于试跑规模时只运行一次，避免重复评测。实际题目数可能少于子集上限。
6. 通过真实任务入口查看进度、脱敏日志和标准 JSON 报告。评测完成后，Codex 读取真实指标，
   保存中文解读；AI 不可用时仍能查看指标并下载报告，也可显式点击“让 AI 解读结果”。
7. “取消评测流程”取消当前试跑或正式评测，并阻止后续自动步骤，不停止模型服务。
8. 助手卡片可“存档”或“删除助手记录”：存档可在 AI 会话中恢复；删除需确认，只清理助手会话、
   方案和解读，下方独立评测成绩及标准报告保留。活动评测需先取消；仅 AI 对话仍运行时，
   删除确认会提示停止该 AI 对话。见 [历史清理入口验收](ai-accuracy-history.md)。

AI 会话在“AI 会话 → 精度评测”单独分类。方案、确认状态、关联任务和解读保存在 SQLite，
原始分数仍属于原有 Accuracy 任务；不会因为 AI 会话结束而变成失败或丢失成绩。

## 实现与权限

- 新任务类型 `accuracy_evaluation`，只允许 Codex，拒绝完整权限模式、部署目标字段和联网搜索。
- SQLite schema 22 → 23 增加 `ai_accuracy_workflows`，不删除或重新评分旧任务。
- Codex 使用进程级 MCP 配置，只加载 `uniform_accuracy`。本机 CLI 验证该覆盖后只列出这一个服务器。
  禁用 shell/unified exec、Apps 和多代理工具；使用只读沙箱，不启用 `auto_review` 或完整权限。
- 专用服务器明确列出 7 个 `enabled_tools`，逐工具设置 `approval_mode="approve"`；默认模式仍为
  `prompt`，未知或未来工具不自动获得权限。该调用许可不替代后台的页面确认、预算、身份与能力令牌校验。
  只读 MCP 提示仅标注检查、状态和日志，方案/启动/取消/解读不伪装成只读工具。
- MCP 子进程使用平台会话能力令牌，不接收平台管理员 API Key；令牌只传环境变量，不写入方案、
  SQLite、工作区 JSON 或命令行。会话结束撤销令牌，续跑时重新签发。
- 专用接口只能操作绑定模型和自身关联的 Accuracy 任务。不能跨会话使用令牌、控制部署或停止模型。
- MCP 仅连接配置好的 `http://127.0.0.1` 控制地址，不跟随重定向，不接受任意 URL/文件/命令。
- AI 提交的样本总量不能超过预算；方案每次修改均生成新 ID，旧确认失效；部署身份变化也拒绝确认。
- 用户确认使用平台鉴权接口，MCP 不提供确认工具；携带 AI 能力令牌的确认请求显式拒绝。
- 模型输出、数据集、日志和 AI 文本是不可信数据，页面以转义文本展示，不执行其 HTML/脚本。
- AI 只可提交带本工作流正式任务 ID 的解读文本，不能通过该接口写指标。
  Markdown 报告的标准分数表由后台读取真实任务生成，AI 解读单独标注“以标准报告数据为准”。
- 控制服务重启后，进行中的工作流标记中断，不自动执行旧批准。需要重新制定和确认方案。
- 写状态失败时清理刚创建的评测；正在运行的工作流禁止直接存档/删除 AI 会话，先取消。
- 全局/创建只读开关沿用阶段 41；关闭创建后禁止新计划与执行，保留状态和结果读取。

## MCP 工具与 HTTP 接口

| 工具 | 职责 |
| --- | --- |
| accuracy_inspect | 已选目标、预算、固定环境身份和数据集白名单 |
| accuracy_propose_plan | 提交待用户确认方案，不请求模型 |
| accuracy_status | 本工作流的试跑/正式任务及标准指标 |
| accuracy_start | 仅启动已确认方案；重复调用不重复创建任务 |
| accuracy_logs | 仅本工作流关联任务的脱敏日志 |
| accuracy_cancel | 仅取消评测，不停止模型服务 |
| accuracy_record_analysis | 保存已完成正式任务的解读，不写入分数 |

工具接口前缀：`/api/v1/ai/sessions/{id}/actions/accuracy/`，使用 `X-AI-Capability`。
用户状态/确认/取消/报告接口：`/api/v1/ai/sessions/{id}/accuracy`、`/confirm`、`/cancel`、`/report`。
工作流列表：`GET /api/v1/accuracy/ai/sessions`。创建 AI 会话仍使用既有的 `POST /api/v1/ai/sessions`。

## 自动验收

```bash
./scripts/accept-ai-accuracy.sh
```

该脚本强制真实 Chromium 和本机 Codex 审批回归，不能通过跳过这些检查来宣称验收通过。
评测流程默认使用模拟 Codex 和模拟 EvalScope；审批回归使用真实 Codex CLI、真实专用 MCP 适配器，
但模型 Responses 接口和平台检查接口均为本地测试服务，不消耗真实模型请求、启动新模型、
修改生产数据库或改动用户 Codex 配置。测试的 Codex 状态与日志放在临时目录，使用临时会话。

覆盖：方案/预算/身份边界、用户确认、先试跑再正式执行、失败/取消不继续、幂等启动、只读开关、
22→23 迁移、重启恢复、状态写入失败清理、能力令牌跨会话/部署越权拒绝、日志/报告脱敏、
MCP 协议握手/stdio/工具调用、真实 Codex 对审批冲突的拒绝与逐工具许可、首次与续聊配置一致、
控制 URL 与重定向拒绝、浏览器自然语言入口/确认/指标/下载、
AI 文本 HTML 注入防护、手机布局和原手动配置保留。

## 已知限制与回滚

- 自动测试证明编排与权限契约，不证明真实 Codex 一定选择最佳数据集；真实 Codex＋真实模型联合
  运行需在用户确认后人工验收。阶段 41 已有的真实成绩不当作本次 AI 联合验收成绩。
- AI 新计划使用新预测；已有缓存恢复、同口径比较沿用原有 Accuracy 任务入口，不让 AI 指定任意缓存路径。
  试跑与正式 limit 不同，因此不强行复用试跑缓存来绕过阶段 41 的严格身份规则。
- 时长依赖数据下载和模型生成速度，当前仅展示明确样本/输出量上限，不编造耗时或计费估算。
- 关闭 AI 会话不会停止已确认的评测；若要阻止正式步骤，需要点击“取消评测流程”。
- MCP 在平台服务账户下运行，并非宿主级隔离执行器；权限边界依赖专用工具、会话能力令牌、API
  鉴权和禁用自由 shell。不要在未信任平台代码的环境中将其视为通用安全沙箱。
- 本机 CLI 必须支持进程级 MCP 配置和已核验的工具开关。未更改用户模型或全局 Codex 配置。
- 回滚优先隐藏 AI 入口或关闭任务创建，保留本版数据读取器、旧任务和真实报告，不降级删除新增表。

临时服务、浏览器、模拟 CLI 和评测进程由测试 fixture 关闭；持久截图仅位于本报告的证据子目录，
可以在确认不再需要时单独清理，不删除生产数据或整棵工作区。
