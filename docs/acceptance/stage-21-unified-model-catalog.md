# 阶段 21：ModelScope 优先的联合模型库

> 当前展示优先级和页面验收已由阶段 22 调整：现在优先展示 Hugging Face，且页面隐藏来源合并
> 信息。以下内容保留为阶段 21 的历史验收记录；当前验收请执行阶段 22。

本阶段将 ModelScope 和 Hugging Face 合并为一个模型库。相同模型名在两边都存在且各自唯一时，
页面只显示一张卡片；ModelScope 是主下载来源，Hugging Face 是备用来源。若同一来源中有多个
发布者使用相同模型名，平台不会冒险合并。量化后缀不同的模型始终独立显示。

模型卡片使用发布组织头像：先解析 Hugging Face 组织头像，再读取 ModelScope 模型元数据中的
`Organization.Avatar`，两边均不可用时使用本地生成的厂商缩写 SVG，不使用站点通用图标。

## 浏览器人工测试

1. 重启服务，打开 `http://127.0.0.1:18180`，进入“模型目录”。来源下拉框默认应显示
   “联合模型库（ModelScope 优先）”。
2. 选择“联合模型库”，搜索一个两站都有的模型，例如 `Qwen3-8B`。预期只出现一张对应卡片，
   卡片显示发布厂商头像和 `Qwen`，而不是 Hugging Face 或 ModelScope 的通用图标。
3. 卡片应显示蓝色 `ModelScope 主来源`；缓存中存在对应 HF 条目时，还应显示黄色
   `Hugging Face 备用`。
4. 点击“AI 一键部署”或“配置部署”。弹窗中的来源应为 `modelscope`，模型 ID 使用卡片主来源
   的实际 ID；本测试无需真正启动大型模型，可关闭弹窗。
5. 分别选择“仅 ModelScope”和“仅 Hugging Face”搜索，确认可以查看单独来源。HF-only 卡片应
   显示 `Hugging Face 备用来源`。
6. 临时断开外网或令 ModelScope 查询失败，再执行联合搜索。页面应提示部分站点不可用并展示
   Hugging Face 在线结果或已有缓存，而不是清空整个列表。
7. 浏览器开发者工具中阻止一个头像请求并刷新。卡片应回退为厂商名称首字母，布局不能塌陷。

通过标准：联合搜索以 ModelScope 为主、相同模型不重复、备用来源可见、部署目标保持主来源，
厂商头像或缩写兜底正常。若量化版本被错误合并、ModelScope 正常时仍因等待 HF 导致搜索明显
阻塞、头像显示为平台通用图标，均不通过。

本阶段测试只读模型目录，不下载权重、不拉取镜像、不启动或停止任何现有容器，无需清理资源。
