# 阶段 38：EvalScope 后台执行与结果归一化

## 阶段边界

本阶段在阶段 37 的数据契约和 Store 上增加后端执行能力，但不新增 HTTP API、前端入口或
`main.py` 接线。阶段 39 才会把这些服务接入应用生命周期和 API。

本阶段包含：

- 共享模型目标解析器，统一解析运行中的平台部署和已验证 AI 部署结果。
- 固定 EvalScope `0.0.0_dev` 与 commit
  `ccb9019ff56fd7dcc8602f4d17b706b31228edca` 的身份校验。
- GSM8K、ARC、C-Eval 数据集清单、子集白名单、评测版本和提示词指纹。
- 每个数据集独立执行，以支持各自的样本上限、子集和 few-shot 参数。
- 后台任务、进度聚合、取消、服务关闭时停止和强制终止进程组。
- EvalScope schema v2 报告的严格读取、边界检查与归一化指标持久化。
- 完成、部分完成、进程失败、身份失败和报告拒绝的明确状态与错误码。

## 安全边界

- EvalScope 使用固定 argv 启动，不经过 shell。
- 模型地址只能来自平台记录，并再次校验为显式端口的回环 HTTP 地址。
- 子进程仅继承运行所需的路径、语言、证书和代理变量；不继承任意业务密钥。
- 模型 API Key 固定为无权限占位值 `EMPTY`，不会写入真实凭据。
- 数据集与框架缓存全部落在当前评测目录。
- 报告必须是评测目录内的普通文件，拒绝符号链接、目录逃逸、超大文件、未知 schema、
  非有限数值和重复归一化指标。
- 取消先向独立进程组发送 `SIGTERM`，超时后发送 `SIGKILL`。

- 运行中任务可取消，第二个并行任务被拒绝。

```text

<run>/evalscope/<序号>-<数据集>/progress.json
```
