# 阶段 18：AI 自主部署模式

自动测试：

```bash
./scripts/accept-stage-18.sh
```

测试验证三种会话模式、Codex 参数、联网能力、Auto-review、完整权限确认、数据库持久化及
会话安全策略。测试使用 fake Codex，不会调用模型额度或执行真实宿主机命令。

## 三种模式

- 自主部署（默认）：`workspace-write + on-request + network access + auto_review`。常规模型检查、
  下载、构建、Docker、日志、探测和重试无需逐条人工确认；需要越过沙箱的动作由 Codex
  Auto-review 判断。
- 交互审批：保持原有 `workspace-write + untrusted`，未知或有副作用的命令交给用户确认。
- 完整宿主机权限：`danger-full-access + never`，没有 Codex 命令沙箱或逐条审批，必须在页面
  明确勾选风险确认。

## 人工测试

1. 从模型卡片点击“AI 一键部署”，确认默认执行模式为“自主部署（推荐）”。
2. 启动一个小模型部署，观察 AI 能连续执行检查、下载、镜像、启动、日志和推理验证，普通
   操作不再逐条等待确认。
3. 确认 AI 会话列表显示“自主”，终端持续显示执行过程。
4. 选择“完整宿主机权限”，不勾选确认时表单必须拒绝提交；勾选后才允许启动。
5. 完整权限模式只应用于该 AI 进程；停止会话后确认进程退出、临时部署 capability 失效。

完整宿主机模式可能读取或修改当前用户可访问的任何数据，应只在用户明确需要、教程可信且
已备份重要数据时使用。平台不保存或自动填写 sudo 密码。
