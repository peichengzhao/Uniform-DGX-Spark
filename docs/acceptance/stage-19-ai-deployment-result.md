# 阶段 19：统一 AI 部署结果

本阶段只统一部署完成后的结果，不扩展权限、隔离、进程治理或其他部署能力。结果固定包含容器、
镜像、端口、启动命令、健康检查和推理测试，同时记录引擎与服务地址。

## 自动测试

```bash
./scripts/accept-stage-19.sh
```

预期最后显示：

```text
PASS: stage 19 unified AI deployment result passed.
```

测试使用 fake Codex 和模拟 Docker inspect，不消耗 AI 额度、不下载权重、不启动容器。它验证：

- 会话 capability 无效时不能提交结果；
- vLLM 受管任务进入 `running` 后可自动生成容器、镜像、端口和可复现启动命令；
- 健康检查和推理测试都通过时状态为 `verified`，任一失败时为 `failed`；
- 同一会话更新结果时保留创建时间，并生成审计事件；
- `uniformctl report --file`、结果 JSON 说明和网页结果面板都存在；
- Python、JavaScript 和 Ruff 检查通过。

## 浏览器人工测试

1. 重启平台，打开 `http://127.0.0.1:18180`，进入“模型目录”或“本地模型”。
2. 对一个可在本机运行的小模型点击“AI 一键部署”，打开对应 AI 终端。
3. vLLM 路径：观察 AI 执行 `./uniformctl deploy` 和 `./uniformctl wait`。等待部署进入运行状态。
4. 终端下方“部署结果”应自动从“等待”变为“已验证”，并显示：
   容器名/ID、镜像、端口、服务地址、完整启动命令、健康检查和推理测试。
5. 展开“启动命令”，确认镜像、端口和模型挂载路径与实际容器一致；运行：

   ```bash
   docker inspect <页面显示的容器名>
   curl -i http://127.0.0.1:<页面显示的端口>/health
   ```

6. 非 vLLM 路径：AI 按 `RESULT_SCHEMA.md` 生成 JSON 并执行：

   ```bash
   ./uniformctl report --file deployment-result.json
   ```

   页面应以完全相同的格式显示结果，不限制其推理引擎或镜像版本。

通过标准：六项结果均与实际部署一致，健康检查和至少一次真实推理都明确通过，页面状态为
“已验证”。若没有结果、任一测试失败却显示“已验证”、启动命令与容器不一致，均不通过。

测试创建的容器和权重仍属于对应部署任务；在部署中心停止容器，确认不再需要后再手工清理
权重。不要在平台正在下载或模型正在运行时删除权重目录。
