# 阶段 29：实时服务日志与请求观察

自动测试：

```bash
./scripts/accept-stage-29.sh
```

人工测试：

1. 对平台托管的部署：打开“部署任务”，点击部署卡片，再点击“实时服务日志”。
2. 对 AI 一键部署的容器：打开对应 AI 会话，在“部署结果”中点击“实时服务日志”。
3. 确认窗口显示正确容器名称，日志可在不刷新页面的情况下更新。
4. 向推理服务发送一次真实请求，确认引擎开启访问日志时，窗口能看到请求路径和 HTTP 状态码；顶部摘要统计当前 1000 行中的请求数和错误数。
5. 分别测试暂停/继续显示、搜索、清空视图、关闭自动滚动和下载日志。
6. 确认日志窗口默认不额外记录 Prompt 或模型响应正文。
7. 如配置了 `UNIFORM_API_TOKEN`，确认未鉴权 WebSocket 连接被拒绝，正常页面可连接。

注意：平台展示容器的真实标准输出。若推理引擎关闭了访问日志，平台不会伪造单次请求记录，需按引擎当前版本的参数重新开启。

通过标准：托管部署与 AI 结果容器都能进入同一实时日志窗口，日志来源受容器名校验和 API Key 保护，无需手工执行 `docker logs` 命令。
