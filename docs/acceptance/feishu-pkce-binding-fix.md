# 飞书绑定 PKCE 故障：修正与脱敏诊断

日期：2026-10-27。范围仅为 `uniform-dgxspark` 的飞书授权绑定，不改变告警规则、模型服务或评测结果。

## 已确认的现象与证据边界

用户截图实际位于 `127.0.0.1` 的平台授权回调页。飞书已回传授权码，平台显示的文案映射到飞书错误码 **20049（PKCE code challenge failed）**。这不是「仍在飞书官方授权页」，也不是普通的本地 state/浏览器失配提示。

旧代码发起授权时使用 `accounts.feishu.cn/open-apis/authen/v1/authorize`，换取用户凭证时使用 `/oauth/v3/token`。匿名、只读请求显示，旧授权入口的登录返回路径会转到 `open.feishu.cn` 的 v1 授权路由；同域的 `/oauth/v3/authorize` 登录返回路径则保留在 `accounts.feishu.cn` 的 v3 授权路由，PKCE 查询参数保持一致。

飞书公开文档存在说明差异：授权页文档的 PKCE 段仍提示搭配 v2 token；v2 迁移文档又明确正确的 PKCE 可直接使用 v3，并指出 v2 曾允许「授权时没有 challenge、换 token 时却有 verifier」的宽松行为。因此本次**不使用 v2 自动降级，不省略 verifier，不关闭 PKCE**。

已有 SHA-256/Base64URL 算法符合 RFC 7636 标准向量。现有证据不足以断言旧入口是此次拒绝的唯一根因：匿名跳转和模拟服务不能替代用户的真实飞书授权。最终需要用户重新扫码确认。

## 本次代码变化

1. 授权与凭证端点配对为同域 v3 流程：`https://accounts.feishu.cn/oauth/v3/authorize` + `https://accounts.feishu.cn/oauth/v3/token`。网页严格校验新授权地址，不接受任意域名或旧路由。
2. 在一次性授权状态中绑定初始 App ID、回调地址、PKCE challenge 和 verifier；发送凭证请求前校验格式、challenge 对应关系、配置未变、state、浏览器 nonce 与有效期。使用同一次授权的值发出请求；不一致则在本地停止，不向飞书交换授权码。
3. 飞书拒绝时保留最近一次脱敏诊断：独立诊断 UUID、失败阶段、时间、HTTP 状态、错误码、符合飞书格式的请求编号及本地校验布尔值。响应正文、原始错误描述、密钥、token、授权码、state、nonce、challenge、verifier、完整 URL 均不进入诊断。
4. 诊断采用显式字段白名单，存入 `data/feishu-private/binding-diagnostic.json`，目录 700、文件 600，原子替换，并在重启后恢复。非法、权限不安全或含多余字段的历史诊断不会回传到页面。诊断持久化失败不绕过授权安全校验。
5. 系统监控页新增「最近绑定诊断」，失败会持续可见，打开新授权会更新为等待完成；手机上可换行。回调页标题明确为 Uniform，并显示脱敏诊断编号和阶段，避免误认成飞书官方页面。
6. 20049 不自动重试，也不拿同一授权码切换接口尝试。用户拒绝授权不交换凭证；成功绑定仍须手动发送测试消息成功后才允许开启告警。

静态资源版本：`20261027-feishu-pkce`。无需数据库迁移，库版本保持 25。现有应用配置与模型服务保持不变。

## 用户重试步骤

1. 关闭所有旧的飞书授权窗口，刷新系统监控页。不要复用截图中或历史窗口中的回调链接。
2. 已保存的应用凭证和回调地址不需要重复填写。点击「扫码绑定我的飞书」，在新开的官方授权页扫码并同意。
3. 成功后返回平台确认绑定身份，然后自行发送测试消息；收到消息后再开启自动告警。
4. 如果仍失败，只发送「最近绑定诊断」中的错误码、阶段、诊断编号或截图。不要发送完整授权链接、回调链接、密钥或校验字符串。若本地校验全通过但飞书仍返回 20049，可使用脱敏请求编号继续核对飞书侧行为。

## 官方依据与在线观察

- [授权码接口](https://open.feishu.cn/document/common-capabilities/sso/api/obtain-oauth-code)：PKCE S256 参数、一次性授权码、回调规则。
- [用户 token v3](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/authentication-management/access-token/get-user-access-token-v3)：form-urlencoded、verifier、20049 错误码。
- [v2 迁移说明](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/authentication-management/access-token/get-user-access-token)：v3 更严格，不能用 v2 宽松行为掩盖缺失 challenge。
- 配对的 v3 授权入口依据官方 `accounts.feishu.cn` 实际只读 HTTP 行为核对：正常参数进入登录流程，缺少 client_id 返回授权错误页面，无效路由返回 404。上述文档并非都已同步列出新授权路径；本次不把匿名可达视为真实用户授权成功。
