## 身份与比较规则

| 身份 | 包含内容 | 用途 |
| --- | --- | --- |
| evaluation_fingerprint | 指纹版本、报告 schema、EvalScope version/commit、数据集 ID/hub/revision/hash、子集、limit、evaluation version、Prompt hash、few-shot、seed、生成参数、批大小和超时 | 判断评测配置口径是否一致，独立于模型 |
| cache_fingerprint | evaluation_fingerprint、模型名、已登记目标的部署快照 | 只在同一模型/目标/部署快照下复用预测 |

两种指纹均用规范 JSON 的 SHA-256。数据集和子集列表顺序规范化；预设标签、时间、输出目录不参与比较身份。
换模型可以保留相同评测口径，但不允许使用另一个模型的预测缓存。

比较还要求：任务为 `completed`、summary 非 incomplete，且指标键、evaluation version、类别、
子集、方向与样本数一致。`partial`、取消、中断、失败、旧版未记录身份的结果不能直接比较。
不同数据集分别列出，不计算全局平均准确率或混合不同指标。

当前数据集 revision/content hash 在无法可靠获取时仍为 `null`。页面所说“同口径”是配置口径一致，
不宣称已锁定远端数据集内容或做到逐比特复现；EvalScope 自身的缓存身份校验继续执行。
模型后端随机性和外部数据修订仍可能影响结果。所有 limit 评测均明确标为抽样，不代表完整官方成绩。
缓存模型身份来自已登记部署快照，不逐文件哈希全部模型权重；手工更换权重时应建立新部署/更新 revision，
不能沿用旧快照后仍把缓存视为当前模型的结果。

## 缓存与恢复安全边界

1. 校验来源任务已停止、评测和模型/部署缓存身份一致。
2. 校验来源目录属于 Accuracy 根目录，平台生成的身份 manifest 与数据库一致。
3. 来源必须已有 `configs/task_config.yaml` 和预测 JSONL，缺失时返回 `409`，不创建空壳任务。
4. 将 `predictions`、`reviews`、`configs` 及相关数据缓存复制到新任务目录；拒绝符号链接、逃逸路径，
   总复制量不超过 2 GB。原任务仍保持原终态，不改写其预测、评分或报告。
5. 只有复制后的当前任务目录会传给 EvalScope `--use-cache`；不将来源路径直接交给 EvalScope 改写。
6. 保存来源 ID，并按 EvalScope 日志实际报告的复用预测数量展示缓存命中，不把“请求复用”当作“已命中”。

同一 Accuracy manager 内复制与删除共用锁，避免来源在复制时被删除。磁盘不足会明确失败；
存在符号链接或超过限制时不能自动改为不受控复制。代码/Agent/LLM Judge 评测仍不在本阶段范围内。

## 真实模型一键验收（显式选择）

以下命令会调用已运行模型并可能下载数据集，不属于普通回归：

```bash

UNIFORM_STAGE41_EVALSCOPE_SOURCE=/home/dgx-spark/Downloads/evalscope \
  ./scripts/accept-stage-41.sh --live
```

命令路径应替换为本机固定 commit 的独立 EvalScope 环境。默认只读检查项目生产数据库中
处于 running 且未存档的托管部署，并核对回环 `/v1/models`；可用 `UNIFORM_STAGE41_SOURCE_DB`
指定另一份登记数据库。不能传任意模型 URL，也不会自动部署或重启模型。

真实验收使用临时控制服务、临时数据库和真实 Chromium；生产数据库只读，Docker 控制被隔离。
依次运行 GSM8K 2/20、20 条缓存复跑、改变生成参数的 2 条、早期取消、隔离实例中断/恢复、
固定 C-Eval 两学科各 2 条与 ARC Easy 2 条。比较与详情由真实浏览器检查，JSON 报告与页面数值核对。
中断模拟只终止临时任务的 EvalScope 进程并执行临时数据库恢复，不重启生产控制服务。
另一个真实用例必须等到任务为 `running` 且持有存活的 EvalScope 子进程后，才从页面取消；
检查子进程退出、任务保留 `started_at`，并再次确认模型 `/v1/models` 可访问。

每任务等待上限 45 分钟，运行期间每 30 秒输出脱敏进度。临时数据库仍在 Pytest 隔离目录，
但结果、截图和下载的 JSON 报告现已独立保存，避免后续 Pytest 自动清理吞掉验收证据。
默认输出到单独创建的 `/tmp/uniform-stage41-evidence-*`，运行时打印 `LIVE_EVIDENCE`；
可用 `UNIFORM_STAGE41_EVIDENCE_DIR` 指定持久目录。输出包括 `stage-41-live-results.json`、
`live-accuracy-comparison.png`、`live-accuracy-result.png`、`reports/` 和
`stage-41-live-cancellation.json`。不同验收批次应使用不同证据目录，避免覆盖同名结果。

## 用户人工浏览器验收

1. 进入“精度评测”，选择运行中的目标，快速预设设为 2，再以快速预设 20 运行。
   预期均标注抽样，指纹因 limit 不同而不同，20 条任务有明确成功/异常统计。
2. 下载原始 `reports/.../gsm8k.json`，核对页面每子集指标和样本数。
   预期 JSON 的得分与页面百分比一致，下载不能获取原始未脱敏日志。
3. 在 20 条结果点“按此配置重跑”，勾选缓存复用；预期配置不变、来源明确、复用数有实测依据。
4. 选择两条同配置完整结果进行比较；预期按数据集/子集展示，不出现综合平均准确率。
5. 改变 few-shot 或生成参数后运行，再比较旧结果；预期明确拒绝直接比较，不显示误导性表格。
6. 取消一个任务，确认模型服务仍在运行；对已有匹配缓存的不完整记录点击恢复。
   预期新任务恢复，旧记录仍保留取消/中断状态，模型或配置改变则拒绝缓存。
7. 固定 C-Eval `computer_network, operating_system`，每子集 2；预期 C-Eval 合计 4 条。
8. 快速关闭并重开详情，预期日志/工件仍能加载；手机宽度检查比较表与操作按钮可访问。
9. 在隔离实例使用 `UNIFORM_ACCURACY_CREATION_ENABLED=false`。
   预期禁止新建/恢复，但历史、比较和原始报告下载仍可访问。
