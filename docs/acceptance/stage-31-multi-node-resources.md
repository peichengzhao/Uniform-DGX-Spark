# 阶段 31：双机 CPU、统一内存、GPU 与容器资源同步监控

自动测试：

```bash
./scripts/accept-stage-31.sh
```

人工测试：

1. `Ctrl+Shift+R` 刷新 `http://127.0.0.1:18180`，进入“系统监控”。
2. 确认同时显示本机和已登记的远端 DGX Spark；每个节点标题下显示本次采样时间，页面停留时约每 3 秒更新显示，SSH 探针约每 5 秒采样。
3. 两个节点均应显示 CPU 实时利用率与核心数、系统统一内存用量、GPU 核心利用率、GPU 内存控制器利用率、温度和功耗。
4. GB10 的 `nvidia-smi` 不提供独立的 `memory.used/total/free`，因此“GPU 显存 / 统一内存池”应显示共享系统内存的可用量并标注“共享”，不能伪装成 GPU 独占显存。鼠标悬停可看到说明。
5. 远端当前运行的 `open-webui` 容器应显示容器名称、镜像、状态、CPU、Docker cgroup 内存占用和网络类型。双机推理容器运行时，两台机器的对应容器也应分别出现在各自节点下。
6. 在远端制造轻量 CPU 或容器请求负载后等待 5～10 秒，确认 CPU/容器资源数值发生变化；刷新过程中不应需要重新填写动态 IP、接口名或容器名。
7. 暂停远端 SSH 或断开网络后，远端卡片应显示离线错误，本机监控继续更新；恢复 SSH 后自动恢复采集。

通过标准：本机和远端资源在同一页面持续更新；数据均来自当次本地/SSH 只读探针；DGX Spark 统一内存与传统独立显存的语义明确区分；容器统计不读取命令行、环境变量、密钥或 Prompt。
