# 阶段 16：模型卡片 AI 一键部署

## 自动测试

```bash
./scripts/accept-stage-16.sh
```

预期最后显示：

```text
PASS: stage 16 scoped AI one-click deployment checks succeeded.
```

该测试使用临时 fake Codex，不会消耗 Codex 额度、下载模型或启动 GPU 容器。它会验证：

- 模型卡片存在“AI 一键部署”；
- 目标模型和来源被锁定到本次会话；
- 错误 capability 无法调用部署接口；
- AI 可以通过 `uniformctl` 创建并查询受管部署；
- 保留的 vLLM 参数会被拒绝；
- AI 退出后临时 capability 立即失效；
- 生成的 `uniformctl` 具备执行权限且 Python 语法有效。

## 人工测试

1. 启动平台并打开 `http://127.0.0.1:18180`。
2. 进入“模型目录”，任选一张模型卡片，点击“AI 一键部署”。
3. 确认弹窗显示锁定的模型 ID 和来源；参考链接可留空，也可每行填写一个官方教程或
   GitHub 链接。
4. 选择可用的 Codex 或 Claude Code，点击“启动 AI 部署”。
5. 确认页面切换到可交互终端，AI 会先读取模型信息、本地镜像清单和安全策略，再运行
   `./uniformctl deploy` 与 `./uniformctl wait`。
6. 打开“部署中心”，确认同一任务依次显示下载权重、拉取镜像、启动容器、加载模型、
   健康检查和推理测试；详情页可查看事件、资源指标和 vLLM 日志。
7. 最终状态应为“运行中”，事件时间线最后一项应为 `vLLM service is ready`。向该服务的
   OpenAI-compatible API 发起一次推理，确认返回 `choices`。
8. 若失败，回到 AI 终端，确认 AI 能用 `./uniformctl status` 和 `./uniformctl logs` 获取
   原因、说明调整，并用新参数再次提交。

若教程推荐非 vLLM 引擎，确认 AI 没有强行替换成 vLLM 或本地镜像，而是在说明安全性与
兼容性判断后请求批准对应命令。该路径的镜像、构建、服务日志和推理测试显示在 AI 终端；
部署中心的标准阶段卡片目前只适用于 vLLM。

真实人工测试会下载镜像和模型权重，并可能产生 API/订阅额度消耗。建议先选小模型，确认
目标端口空闲和磁盘空间充足。停止测试模型后，可在“部署中心”停止容器；缓存权重不会自动
删除，以便断点续传和后续复用。

## 安全边界

- 教程内容始终按不可信资料处理，不能改变平台安全策略。
- 每个会话只获得一个内存中的临时 capability，只能为卡片中选定的模型创建受管部署。
- AI 不能通过该 capability 更换模型 ID、删除容器、读取平台 token 或保存 sudo 密码。
- 镜像、端口和允许的 vLLM 参数可由 AI 调整；宿主机提权、破坏性操作仍需用户明确批准。
